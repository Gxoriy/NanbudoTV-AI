# 剧情分场策划

本版由用户提供的“剧情分场策划”Skill适配为短剧工作流内置策划器。保留按故事因果、人物目标和阶段结果判断边界的核心方法，使用应用提供的完整原文单元。

## 业务层级与范围

- 本应用“一集＝一场”，只有一层剧情目录。每场后续再展开多个镜头，按顺序组成数张视频卡；本轮不补镜头、不设15秒切片、不提取资产。
- 调用此Skill表示用户选择重新策划。已有集号与边界作为参考，可以按当前剧情重新划分，不把原标签或地点变化强制当成新的集／场。
- 分离过的标题、时长、版本与制作说明属于元信息，不编成黑底字幕、片头、角色对白或新剧情。原文明示要出现在画面的屏幕文字、告示、声音仍是故事内容。
- 当前任务是整理和分场，不擅自改写人物、对白、因果、时间顺序或结局。没有故事细节的大纲不扩成完整剧本。

## 执行

1. 按[分场导演指令](references/segmentation-instruction.md)判断故事任务、自然边界、标题与承接。
2. 按[应用输出合同](references/output-contract.md)选择连续的原文单元编号，并返回紧凑JSON。原文由程序按编号取回，不重抄全文。
3. 参照[边界示例](references/examples.md)处理问答、电话、闪回、并行线与同地不同任务，不把示例人物或剧情加入输入。
4. 内部复核范围完整有序、边界不割裂因果、标题概要有原文依据。无需输出推理过程或自评分。

## 大剧本承接

应用按已发布模型的输入与输出容量提供连续原文范围。每次请求中的`contextBefore`与`contextAfter`只供理解接续，不能计入本次范围。技术请求边界不是剧情边界；若本批第一段仍延续前批末尾的同一剧情任务，返回`continuesPrevious: true`，应用按原文顺序归为同一场。

本Skill只产出策划结果。原文、模型原返回、真实任务状态、费用及历史版本由应用记录，不能声称已生成视频、已修改项目或已经核实全部尚未提供的原稿。
