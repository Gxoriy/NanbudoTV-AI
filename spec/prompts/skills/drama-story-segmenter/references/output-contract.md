# 应用输出合同 v198

应用提供`originalUnits`，每项为`[单元编号, 原文]`。编号从1开始，本批重新编号；`sourceStart`、`sourceEnd`均包含端点，不是字符偏移。标题、概要与承接属于策划元信息，不替代原文。

返回一个JSON对象：

```json
{
  "units": [
    {
      "sourceStart": 1,
      "sourceEnd": 8,
      "title": "获得机会·答应试工",
      "synopsis": "仅概括本场已有的人物、行动及阶段结果。",
      "handoff": ["下一场需要继承的新增事实"],
      "boundary_reason": "有必要时一句话说明边界依据",
      "continuesPrevious": false
    }
  ]
}
```

示例编号与内容仅用于说明字段，按实际输入返回，不凑固定数量。首项从1开始，每项紧接前项，最后覆盖`unitCount`。一个场次可以覆盖任意数量的连续单元；不能把单元本身误当作场次。输出标题、简洁概要和必要承接，不重抄全文、镜头或视频提示词。

`continuesPrevious`只用于本批第一项：若`hasPreviousBatch`为true，且本批开头与`contextBefore`末尾仍是同一剧情任务，把它设为true。若已经转入新任务则false；第一批及本批其余项均为false。应用会拼接同一任务跨批的原文和策划信息；不是新增模型合并调用。

可附`notes`说明材料不明确处。不需要自造项目ID、场次ID、源文hash或字符偏移；这些由程序生成。使用`units`作为列表，但额外解释字段不会导致整份模型原返回被丢弃。

本轮输入已经按容量划分；不得声称覆盖上下文或未提供的尾部。应用先保存原返回，再做范围对应；无法对应的结果仍供查看，但不能悄悄删改原文或作为完整目录覆盖现有项目。
